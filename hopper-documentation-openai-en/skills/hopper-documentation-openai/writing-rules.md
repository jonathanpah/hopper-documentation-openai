# Writing rules

They apply to documents 3 to 7. ADHD-friendly format, without talking down and without sacrificing precision.

1. Start with the conclusion. Then explain only what is needed, in logical order and without skipping indispensable steps.
2. Write for an intelligent reader who does not know the subject. Do not talk down and do not assume technical knowledge.
3. Start each block of the simplified conversation with 1 line that states the subject.
4. Write one idea per sentence and one subject per paragraph, with up to 6 sentences.
5. Use up to 20 words per sentence in instructions and up to 25 in explanations.
6. Write one action per instruction, with the verb in the imperative.
7. Use the active voice and direct order, without interpolated clauses.
8. Use common, literal words, without jargon, and the same term for the same concept.
9. Explain each technical term or acronym the first time it appears.
10. Prefer verbs to nouns. For example, "check", not "perform a check".
11. Cut introductions, repetitions, redundancies, flourishes, tangents, recaps, dispensable examples and generic closings.
12. Never omit facts, numbers, risks, limits, caveats or concepts. Cutting redundancy must not erase a concept.
13. Use headings and lists only when they make reading easier. Put in bold what the reader must retain.
14. Each pending item states what is pending, the recommendation and what depends on the user. A suggestion is not a pending item.

## Fidelity rules

15. Distinguish fact, report, proposal and decision. Without evidence in the conversation, write "reported, not verified".
16. An authorization is valid only in the scope stated. Recording a pending item does not authorize executing it.
17. The latest version of a fact prevails in every document. A missing record does not prove that something did not happen.
18. Every statement in documents 3 to 7 cites its source message.
